# What NewPipe can teach us about player features

> Research notes, 2026-11-27. Read-only research: no project code was changed.
> Scope: recommendations, audio track selection, aspect-ratio/scaling modes, player gestures, player/quick settings.
> All NewPipe facts below were verified against the `dev` branch at commit `62c87aa6b7556e260d5639da1d23240cfba17e6e` (2026-11-24) and NewPipeExtractor at `ebc0b8c8b1e08300d54ce6413720b33695cd6075`. Links are permalinks to those commits.
> Convention note: this repo currently keeps Ukrainian design/plan docs under `docs/superpowers/`; there was no `docs/research/` convention, so this file uses the requested path and English (the request was in English).

## Summary

- **Recommendations** are not a separate network feature in NewPipe: the extractor returns `StreamInfo.relatedItems` from the same page load as the video metadata (YouTube: the `next` endpoint's `secondaryResults` list). The app wraps that list into a `RelatedItemsInfo`/`RelatedItemsFragment`, shows it as a tab on phones and a side panel on tablets, and also uses it for optional "auto-queue next stream".
- **Audio track selection is source-level, not ExoPlayer-track-level.** NewPipe picks a different `AudioStream` URL (identified by `audioTrackId`), re-resolves the media source and reloads the queue. It deliberately does *not* use `DefaultTrackSelector.setParameters()` for audio. The UI hides the audio button when there is fewer than one track and labels tracks as "Language (type)".
- **Scaling** is the ExoPlayer `AspectRatioFrameLayout` model: `FIT` (letterbox), `FILL` (ignore ratio / stretch), `ZOOM` (crop to fill). A single text button cycles FIT → FILL → ZOOM and persists the choice in `SharedPreferences`. NewPipe does not offer a separate "stretch" beyond `FILL`.
- **Seek gestures** are *multi double-tap* on the left/right thirds (not single-tap zones). A single tap only toggles controls. Repeated taps within 550 ms accumulate `seekDuration` (default 10 s) with an animated seconds counter and arc overlay.
- **Volume/brightness swipes** are vertical fullscreen-only gestures on screen halves. Defaults are exactly what we want: **left = brightness, right = volume**, each independently configurable to volume/brightness/none.
- **Quick settings** are two control rows in one layout: a primary row (title, audio track, quality, speed, queue, chapters, "more") and a secondary row revealed by "more" (resize, captions, Kodi, browser, share, mute, fullscreen). Popup menus are rebuilt from current track metadata on every update.

## 1. Recommendations / suggested videos

### Verified facts

- Data source: `StreamInfo` gets related items during stream extraction, in `StreamInfo.build()` via `ExtractorHelper.getRelatedItemsOrLogError(streamInfo, extractor)` — no second screen-specific request is made by the UI. ([StreamInfo.java:365-367](https://github.com/TeamNewPipe/NewPipeExtractor/blob/ebc0b8c8b1e08300d54ce6413720b33695cd6075/extractor/src/main/java/org/schabi/newpipe/extractor/stream/StreamInfo.java#L365-L367), [StreamInfo.java:638-651](https://github.com/TeamNewPipe/NewPipeExtractor/blob/ebc0b8c8b1e08300d54ce6413720b33695cd6075/extractor/src/main/java/org/schabi/newpipe/extractor/stream/StreamInfo.java#L638-L651))
- For YouTube the items come from the **`next` endpoint** (`POST`, body contains `videoId`, `contentCheckOk`, `racyCheckOk`), specifically `contents.twoColumnWatchNextResults.secondaryResults.secondaryResults.results`. The extractor maps `compactVideoRenderer`, `compactRadioRenderer`, `compactPlaylistRenderer` and `lockupViewModel` into `StreamInfoItem`/playlist items; age-limited videos return `null` related items. ([YoutubeStreamExtractor.java:754-806](https://github.com/TeamNewPipe/NewPipeExtractor/blob/ebc0b8c8b1e08300d54ce6413720b33695cd6075/extractor/src/main/java/org/schabi/newpipe/extractor/services/youtube/extractors/YoutubeStreamExtractor.java#L754-L806), [YoutubeStreamExtractor.java:826-850](https://github.com/TeamNewPipe/NewPipeExtractor/blob/ebc0b8c8b1e08300d54ce6413720b33695cd6075/extractor/src/main/java/org/schabi/newpipe/extractor/services/youtube/extractors/YoutubeStreamExtractor.java#L826-L850))
- The app wraps them with `RelatedItemsInfo extends ListInfo<InfoItem>` (`setRelatedItems(new ArrayList<>(info.getRelatedItems()))`). It is a pure in-memory wrapper — `loadResult()` returns the same object and `loadMoreItemsLogic()` returns an empty page, i.e. **no pagination of recommendations**. ([RelatedItemsInfo.java:11-21](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/fragments/list/videos/RelatedItemsInfo.java#L11-L21), [RelatedItemsFragment.java:92-104](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/fragments/list/videos/RelatedItemsFragment.java#L92-L104))
- UI placement: on phones it is tab `RELATED_TAB_TAG` ("NEXT VIDEO") in `VideoDetailFragment`'s pager alongside Comments and Description; on tablets/TV it is a dedicated `relatedItemsLayout` side panel that is hidden in fullscreen. It is optional (`show_next_video` preference). ([VideoDetailFragment.java:893-975](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/fragments/detail/VideoDetailFragment.java#L893-L975), [VideoDetailFragment.java:954-964](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/fragments/detail/VideoDetailFragment.java#L954-L964))
- The list header contains an **autoplay/auto-queue switch** bound directly to the `auto_queue_key` preference; the same preference appears in Settings → Video & audio → Behavior. ([related_items_header.xml:1-31](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/layout/related_items_header.xml#L1-L31), [RelatedItemsFragment.java:73-90](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/fragments/list/videos/RelatedItemsFragment.java#L73-L90), [video_audio_settings.xml:175-181](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/xml/video_audio_settings.xml#L175-L181))

([PlayerHelper.java:159-204](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/helper/PlayerHelper.java#L159-L204), [video_audio_settings.xml:175-181](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/xml/video_audio_settings.xml#L175-L181))

([MainPlayerUi.java:628-667](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/MainPlayerUi.java#L628-L667))

### Implementation ideas (inference, not NewPipe behaviour)

- NewTube already renders a related shelf in `app/src/main/java/com/example/newtube/ui/video/WatchScreen.kt:138-149`. Copy NewPipe's key property: **one metadata fetch feeds both the watch page and the recommendations** — do not add a second "related videos" API call unless the current detail response lacks it.
- Reuse the related list for a "up next" queue with NewPipe's dedup-by-video-id rule and a single global toggle. Keeping the queue and the shelf derived from the same model avoids drift.
- In fullscreen there is no room for the shelf. NewPipe hides recommendations entirely in fullscreen; a NewTube improvement would be a slide-up drawer using the existing `itemsListPanel` pattern (queue/chapters), populated from the same related list, with an autoplay switch in the header.

## 2. Audio track selection

### Verified facts

- NewPipe's audio menu is built from `MediaItemTag.AudioTrack` attached to the current `MediaItem`, not from `ExoPlayer.getCurrentTracks()`. `buildAudioTrackMenu()` rebuilds the `PopupMenu` group, labels via `Localization.audioTrackName()`, and **returns early if fewer than two tracks** (button stays hidden). ([VideoPlayerUi.java:1182-1208](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java#L1182-L1208), [Localization.java:340-357](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/util/Localization.java#L340-L357))
- Labels are `Locale.getDisplayName()` (or extractor name) plus a localized type: Original / Dubbed / Descriptive / Secondary. ([Localization.java:340-357](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/util/Localization.java#L340-L357))
- Selecting an item calls `player.setAudioTrack(audioStream.getAudioTrackId())`. `Player.setAudioTrack()` saves progress, sets recovery state, updates **both** resolvers and calls `reloadPlayQueueManager()` — i.e. a source reload/resume, not an in-place decoder track switch. ([VideoPlayerUi.java:1371-1390](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java#L1371-L1390), [Player.java:2373-2386](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/Player.java#L2373-L2386))
- Resolver side: `ListHelper.getAudioFormatIndex(context, streams, trackId)` finds the stream with the matching `audioTrackId`, falling back to the ranked default. `VideoPlaybackResolver` then adds a separate audio `MediaSource` when the video is video-only **or** the user explicitly chose an audio track, merging everything with `MergingMediaSource(true, ...)`. ([ListHelper.java:127-158](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/util/ListHelper.java#L127-L158), [VideoPlaybackResolver.java:74-129](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/resolver/VideoPlaybackResolver.java#L74-L129), [VideoPlaybackResolver.java:164-168](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/resolver/VideoPlaybackResolver.java#L164-L168))
- Default ranking: prefer original audio (default on), then preferred locale language, then Original > Dubbed > Descriptive (reversed when "prefer descriptive audio" is on), then English. Both toggles live in Settings → Video & audio. ([ListHelper.java:802-864](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/util/ListHelper.java#L802-L864), [video_audio_settings.xml:54-78](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/xml/video_audio_settings.xml#L54-L78))
- NewPipe's `DefaultTrackSelector` is configured for video quality, tunneling and disabling text/video renderer types — **not** for audio language selection. ([Player.java:298](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/Player.java#L298), [Player.java:2254](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/Player.java#L2254))
- Upstream Media3 docs describe the alternative we can use: `Player.setTrackSelectionParameters()` with constraints (`setPreferredAudioLanguage`) before playback, or `TrackSelectionOverride(audioTrackGroup, index)` after querying `getCurrentTracks()`; overrides only apply to media items with an exactly matching `TrackGroup`. ([Media3 track selection](https://developer.android.com/media/media3/exoplayer/track-selection))

### Implementation ideas (inference, not NewPipe behaviour)

- NewTube's `VideoPlayer.kt:92-145` already owns a `DefaultTrackSelector` and already listens to `onTracksChanged` (`:172-183`). Add an audio track menu that filters `Tracks.Group` by `C.TRACK_TYPE_AUDIO`, uses `Format.language`/`roleFlags` for labels, and applies `setOverrideForType(TrackSelectionOverride(...))`. This is **simpler and gapless** than NewPipe's source reload for in-band (HLS/DASH) audio.
- If a service exposes alternate audio as **separate URLs** (NewPipe's case), an override cannot help: follow NewPipe and re-resolve the source with a stable track id, saving/restoring position (NewTube already has `onSavePosition` and resume logic at `VideoPlayer.kt:156-161`).
- Copy two UI rules: hide the audio button for a single track, and show "Language (type)" rather than codec/bitrate. Store a preferred-language/type ranking in settings so it applies to every video (Media3 constraints do this automatically; NewPipe implements it manually).
- Beware: `TrackSelectionOverride` is per-media-item. Reapply stored preferences on `onTracksChanged` / each new `MediaItem`, otherwise the next video silently falls back.

## 3. Aspect ratio / scaling modes

### Verified facts

- Modes are ExoPlayer's `AspectRatioFrameLayout`: `RESIZE_MODE_FIT` ("decrease width or height to obtain the desired ratio"), `RESIZE_MODE_FILL` ("specified aspect ratio is ignored" → stretch), `RESIZE_MODE_ZOOM` ("increase width or height" → crop-to-fill). FIT/FILL/ZOOM are the only modes NewPipe supports; FIXED_WIDTH/FIXED_HEIGHT throw from `resizeTypeOf()`. ([AspectRatioFrameLayout.java](https://github.com/androidx/media/blob/release/libraries/ui/src/main/java/androidx/media3/ui/AspectRatioFrameLayout.java), [PlayerHelper.java:142-157](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/helper/PlayerHelper.java#L142-L157))
- The label button lives in `secondaryControls`, is initially `FIT`, and a tap calls `nextResizeModeAndSaveToPrefs()` with cycle FIT → FILL → ZOOM → FIT; the result is saved under `last_resize_mode` and restored at player init. ([player.xml:277-299](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/layout/player.xml#L277-L299), [VideoPlayerUi.java:1613-1620](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java#L1613-L1620), [PlayerHelper.java:410-438](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/helper/PlayerHelper.java#L410-L438), [MainPlayerUi.java:285-289](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/MainPlayerUi.java#L285-L289))
- Aspect ratio is set from `Player.Listener.onVideoSizeChanged`: `surfaceView.setAspectRatio(width / height)`; zero-size events (renderer disabled, ExoPlayer ≥ 2.19) are ignored. NewPipe uses ExoPlayer **2.19.1** (Media3 1.7.1 is present only for compatibility). ([VideoPlayerUi.java:1622-1631](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java#L1622-L1631), [libs.versions.toml:27,48](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/gradle/libs.versions.toml#L27))
- Upstream notes: `PlayerView.setResizeMode()` forwards to the internal `AspectRatioFrameLayout`; `updateAspectRatio()` computes `(width * pixelWidthHeightRatio) / height`, with 1% deformation tolerance before relayout. ([PlayerView.java](https://github.com/androidx/media/blob/release/libraries/ui/src/main/java/androidx/media3/ui/PlayerView.java), [AspectRatioFrameLayout.java](https://github.com/androidx/media/blob/release/libraries/ui/src/main/java/androidx/media3/ui/AspectRatioFrameLayout.java))

### Implementation ideas (inference, not NewPipe behaviour)

- NewTube's `VideoPlayer.kt:75` already accepts `resizeMode` with FIT as default — this is exactly NewPipe's default. Wire a labelled cycle button (FIT → FILL → ZOOM) and persist it in DataStore/SharedPreferences with the same key pattern.
- Keep the names honest: NewPipe's "Zoom" is crop-to-fill, "Fill" is stretch. If we expose a fourth "Fit (portrait)" or contain-inside-safe-area option, that is our own addition, not NewPipe's.
- Use Media3's `pixelWidthHeightRatio` rather than raw `width/height` (NewPipe's 2.19 code ignores it) to handle anamorphic sources correctly.
- `PlayerView` already owns `AspectRatioFrameLayout`, so no custom measurement code is needed: `playerView.setResizeMode(...)` plus a persisted Int is enough.

## 4. Gestures: tap zones for seek, fullscreen volume/brightness swipes

### Verified facts — tap/seek

- Base class `BasePlayerGestureListener` extends `GestureDetector.SimpleOnGestureListener` and forwards touches from the player root via a `GestureDetector`; it returns `false` from `onTouch` so the view hierarchy can still receive events. ([BasePlayerGestureListener.kt:20-30](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/BasePlayerGestureListener.kt#L20-L30))
- A **single tap never seeks**: `onSingleTap()` only shows/hides controls (or shows them permanently when playback is completed). ([BasePlayerGestureListener.kt:56-69](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/BasePlayerGestureListener.kt#L56-L69), [MainPlayerGestureListener.kt:55-69](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/MainPlayerGestureListener.kt#L55-L69))
- Screen is split into **thirds**: `x < width/3` = LEFT, `x > 2*width/3` = RIGHT, else MIDDLE. Double-tapping LEFT/RIGHT starts "multi double tapping"; MIDDLE toggles play/pause. ([MainPlayerGestureListener.kt:220-226](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/MainPlayerGestureListener.kt#L220-L226), [BasePlayerGestureListener.kt:32-54](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/BasePlayerGestureListener.kt#L32-L54))
- Multi double tap: `startMultiDoubleTap()` sets `isDoubleTapping` and a 550 ms handler timer; every further tap calls `keepInDoubleTapMode()` (resets timer) and adds another `seekSeconds` to the overlay counter. Direction can be switched mid-series and the counter resets. ([BasePlayerGestureListener.kt:127-178](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/BasePlayerGestureListener.kt#L127-L178), [PlayerFastSeekOverlay.kt:54-110](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/views/player/PlayerFastSeekOverlay.kt#L54-L110))
- Seek amount: `seek_duration` preference, default **10000 ms**, options 5–30 s. `Player.fastForward()/fastRewind()` call `seekBy(±seekDuration)`. ([settings_keys.xml:35-54](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/values/settings_keys.xml#L35-L54), [Player.java:1841-1850](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/Player.java#L1841-L1850), [VideoPlayerUi.java:326-329](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java#L326-L329))
- Direction guards: left third rewinds unless position < 500 ms; right third fast-forwards unless completed/at duration; middle returns `NONE` and ends the multi-tap mode. ([VideoPlayerUi.java:341-369](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/ui/VideoPlayerUi.java#L341-L369))
- Feedback is a dedicated custom view `PlayerFastSeekOverlay` (`player.xml` `@+id/fastSeekOverlay`) containing `SecondsView` + `CircleClipTapView`; constraints flip the counter to the tapped side and it animates in/out. ([PlayerFastSeekOverlay.kt:17-35,112-126](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/views/player/PlayerFastSeekOverlay.kt#L17-L35), [player.xml:824](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/layout/player.xml#L824))

### Verified facts — volume/brightness swipes

- `MainPlayerGestureListener.onScroll()` **returns immediately unless the main player is fullscreen**, and ignores drags starting in the status/navigation bars. It requires ≥ 40 px vertical movement (`MOVEMENT_THRESHOLD`) and `|dy| >= |dx|`. ([MainPlayerGestureListener.kt:167-196,238](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/MainPlayerGestureListener.kt#L167-L196))
- Side is decided by the *initial* touch position using **halves** (`x < width/2` → left), with the action looked up from `left_gesture_control` / `right_gesture_control` preferences. ([MainPlayerGestureListener.kt:198-215,228-233](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/MainPlayerGestureListener.kt#L198-L215), [PlayerHelper.java:214-224](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/helper/PlayerHelper.java#L214-L224))
- Defaults: **left = brightness, right = volume**; each preference offers volume / brightness / none. ([settings_keys.xml:206-233](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/res/values/settings_keys.xml#L206-L233))
- Volume maps the system `AudioReactor.volume / maxVolume` onto a `ProgressBar`, with icon thresholds at 0/25/75 %. Brightness writes `WindowManager.LayoutParams.screenBrightness` (0..1) and persists it via `PlayerHelper.setScreenBrightness()`. ([MainPlayerGestureListener.kt:71-155](https://github.com/TeamNewPipe/NewPipe/blob/62c87aa6b7556e260d5639da1d23240cfba17e6e/app/src/main/java/org/schabi/newpipe/player/gesture/MainPlayerGestureListener.kt#L71-L155))
- The matching overlays (`volumeRelativeLayout`, `brightnessRelativeLayout`) fade/scale in over 200 ms and out after gesture end; controls are hidden on scroll end. ### Implementation ideas (inference, not NewPipe behaviour)

- NewTube's player is Compose (`VideoPlayer.kt`) with `isFullscreen` already a parameter (`:79`). Add a single `pointerInput` gesture detector on the `PlayerView` wrapper:
  - tap: toggle controls only (preserve `PlayerView`'s existing controller behaviour);
  - double tap in thirds: repeat-seek with a 550 ms accumulator window and a small Composable overlay showing `+N s` / `-N s`;
  - vertical drag in fullscreen: left brightness, right volume, with 40 px start threshold and half-screen split.
- Use Android's `AudioManager` for volume and `Window.LayoutParams.screenBrightness` for brightness, as NewPipe does; persist brightness so it survives leaving fullscreen.
- Make both sides configurable (volume/brightness/none) in settings — this is cheap (two enum prefs) and matches user expectations from YouTube/VLC.
- Do **not** make single taps seek. NewPipe deliberately reserves single tap for controls; changing that breaks the established muscle memory and conflicts with `PlayerView` controller taps.

### Implementation ideas (inference, not NewPipe behaviour)

- Adopt the two-tier idea in Compose: a compact primary row that is always legible, and a "more" row for rarely used controls (resize, captions, share, mute). NewTube's `VideoPlayer.kt:332-341` currently exposes fullscreen/PiP/buttons individually; group them behind the same pattern rather than adding more permanent buttons.
- Rebuild track menus from live `Tracks` on `onTracksChanged` (NewTube already has that callback) and key menu items by immutable track identity, not index, to avoid selecting the wrong track after a source reload.
- Keep "advanced player internals" (tunneling, decoder fallback) out of the quick menu — NewPipe puts them in a nested ExoPlayer settings screen. This keeps the in-player overlay approachable.
